# Domain-driven runtime types

JIT's domain primitives are presets over the same schema AST, class plan, execution plan, and compiled operations used by validation and transport. They are not independent frameworks.

Use the smallest semantic primitive that describes the domain:

- `JIT.class(schema)` materializes validated state.
- `JIT.ddd.valueObject(schema)` adds structural equality, hashing, and immutability.
- `JIT.ddd.entity(schema, { id })` adds identity semantics and is intended to be subclassed.
- `JIT.ddd.aggregateRoot(schema, { id })` adds controlled internal mutation and an ordered domain-event buffer.
- `JIT.ddd.domainEvent(type, { version, payload })` describes an immutable versioned fact.
- `JIT.ddd.uniqueIdentifier(schema?)` creates an identifier-like scalar Value Object and defaults to a generated UUID.

All five are SchemaLike. They can be passed directly to `JIT.validate.parse`, `JIT.json.parse`, `JIT.json.stringify`, mapping, and AOT generation.

| Runtime Type | Default construction |
| --- | --- |
| `JIT.class` | direct `new` |
| Value Object | `create` / `hydrate` factories |
| Entity | `create` / `hydrate` factories |
| Aggregate Root | `create` / `hydrate` factories |
| Domain Event | `create` / `hydrate` factories |

There is no dual default. Factory-built Runtime Types expose an abstract
construct signature to TypeScript and guard their generated constructor with a
module-private token at runtime.

See [factories and construction](./factories-and-construction), the focused
guides in this directory, and [the architecture](../architecture.md).
