```ts
const User = JIT.object({ id: JIT.number().int32(), name: JIT.string().min(2) });

export const UserOps = {
  is: JIT.validate.is(User),
  parse: JIT.validate.parse(User),
};

export const isUser = JIT.validate.is(User);
```

An artifact object generates one object import:

```ts
import { UserOps } from "./generated/index.js";
UserOps.is(input);
```

A standalone artifact keeps its exact declared name:

```ts
import { isUser } from "./generated/index.js";
```

Generated modules contain no import from `jit`. Only the declared operations and the
low-level helpers they need are emitted. This matters most in browser bundles:
importing one validator cannot retain schema builders, codecs, queries or the runtime
compiler.

Bindings that cannot be serialized, such as a callback that closes over its scope, are
skipped with a reason instead of being miscompiled — declaring the transformation with
[`JIT.ops`](/docs/reference/functions/ops) avoids that entirely.

## Object versus standalone

An artifact object is an ergonomic domain module. Standalone artifacts are finer
tree-shaking units. If one route needs only `is`, importing an artifact object
that also declares parse/stringify can retain those siblings depending on how
the object is consumed.

```ts
export const isUser = JIT.validate.is(User); // narrowest unit
export const UserOps = {
  is: JIT.validate.is(User),
  parse: JIT.validate.parse(User),
};
```

## Generated output

Generation writes exactly `index.ts` or `index.js`. `output.perFile` adds one
module per declaration file plus a barrel, so a route bundle can import a
single declaration group without evaluating the others.

The default `output.format: "ts"` writes typed source. Its public structural
types and signatures are annotations on the executable exports, while internal
generated loops remain allocation-conscious low-level code. After the
application compiles that file, the bundle contains the same specialized
JavaScript and no JIT runtime import.

```ts
// single index (default)
import { UserOps } from "./generated/jit/index.js";

// output.perFile: true
import { UserOps } from "./generated/jit/users.js";
```

## Helper retention

Operation-specific helpers are emitted only when needed. A validator that does
not parse cannot retain `JITValidationError`; a query that touches `id` and
`score` cannot retain an unrelated string dictionary; a standalone `is` cannot
retain codec or mapper infrastructure.

Callback-free `JIT.state.watch` functions can also be declared standalone or as a
member of an artifact object. Their generated module retains only the keyed diff loop;
stateful `JIT.state.watchedList` instances remain runtime-owned. See [watched
lists](/docs/runtime/watched-lists#aot-standalone-function).

## Proof, not assumption

The repository bundles generated fixtures through esbuild and asserts that
unused exports/helper classes disappear. Applications should also inspect their
actual Vite/Next/Webpack output because grouping and re-export barrels can alter
tree-shaking boundaries.
