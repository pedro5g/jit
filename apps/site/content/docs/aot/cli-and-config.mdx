---
title: CLI and configuration
description: Initialize, inspect, generate and clean an AOT project.
---

```bash
pnpm jit init
pnpm jit doctor
pnpm jit list
pnpm jit inspect isUser --stage source
pnpm jit generate
pnpm jit clean
```

`init` detects the project — a `tsconfig.json` gets `jit.config.ts` with
TypeScript output, anything else gets `jit.config.js` with ready-to-run ESM —
and writes a starter `*.jit.ts` declaration next to it. Review those two files,
declare the operations the application uses, then run `generate`.

## Complete local setup

```ts title="jit.config.ts"
import { AOT } from "@jit-compiler/jit";

export default AOT.defineConfig({
  entries: ["src/aot/**/*.jit.ts"],
  output: {
    directory: "src/generated/jit",
    format: "ts",
  },
});
```

```ts title="src/aot/users.jit.ts"
import { JIT } from "@jit-compiler/jit/define";

// A schema names the generated type; it emits no runtime function on its own.
const User = JIT.object({
  id: JIT.number().int32(),
  name: JIT.string().min(2),
  role: JIT.union(JIT.literal("admin"), JIT.literal("member")),
});
const Users = JIT.array(User);

// An object of artifacts becomes one frozen object: Users.is(), Users.parse().
export const UserOps = {
  is: JIT.validate.is(User),
  parse: JIT.validate.parse(User),
};

// A standalone artifact keeps its declaration name exactly.
export const findAdmins = JIT.cqrs
  .query(Users)
  .filter((q) => q.eq("role", "admin"));
export const watchUsers = JIT.state.watch(Users, { key: "id" });
```

```ts title="src/app.ts"
import { findAdmins, type User, UserOps } from "./generated/jit/index.js";

const admins: User[] = findAdmins(payload);
```

The declaration file is the manifest. `export` is optional: JIT generates every
top-level artifact and artifact object it finds, and every schema becomes an
exported type named after its binding.

## Configuration reference

| Setting            | Default                      | Purpose                                                |
| ------------------ | ---------------------------- | ------------------------------------------------------ |
| `entries`          | root discovery               | declaration files, directories, or globs               |
| `patterns`         | `**/*.jit.ts`, `**/*.jit.js` | patterns used for directory and root discovery         |
| `output.directory` | `generated`                  | destination relative to the config file                |
| `output.format`    | `ts`                         | `ts` for typed source, `js` for ready-to-run ESM       |
| `output.perFile`   | `false`                      | one module per declaration file plus an `index` barrel |

Generated output is always replaced. JIT deletes only the files it owns —
identified by the generated banner, never by name — so a hand-written file in
the same directory is safe.

## Output layout

The default is one self-contained module:

```
src/generated/jit/
  index.ts
```

`output.perFile` names each module after the declaration file it came from and
adds a barrel that re-exports everything:

```
src/generated/jit/
  index.ts     // re-exports both
  users.ts     // from src/aot/users.jit.ts
  orders.ts    // from src/aot/orders.jit.ts
```

Both layouts import the same way, so the choice is purely about how your
bundler splits code:

```ts
import { findAdmins } from "./generated/jit/index.js";
import { findAdmins as fromModule } from "./generated/jit/users.js";
```

## TypeScript or JavaScript output

`ts` keeps the public signatures in the executable source itself. Type
resolution belongs to the application's own build: JIT writes no `.d.ts`, and
the generated module still has zero imports.

`js` emits the same optimized functions as ready-to-run ESM for projects that
do not typecheck their sources.

## Inspection before generation

```bash
pnpm jit doctor   # config discovery, output target, declaration files
pnpm jit list     # every declared type, artifact object and artifact
pnpm jit inspect isUser --stage source
```

`inspect --stage plan` prints the artifact descriptor instead of the generated
source. Both compile into a temporary directory and write nothing to the
project.

## Watch mode

```bash
pnpm jit generate --watch
```

Declaration files are reloaded on every run, so edits are always picked up.

## Cleaning

```bash
pnpm jit clean
```

Removes the configured output directory. `generate` already replaces its own
files, so `clean` is only needed when retiring a directory entirely.
