One schema can drive multiple independent compilers. Generate only what the
application imports.

## Validation

```ts
JIT.validate.is(User);
JIT.validate.parse(User);
JIT.validate.safeParse(User);
JIT.validate.async.parse(User);
JIT.validate.issues(User);
```

`is` is fail-fast. `safeParse` collects issues and transformed output. `parse`
throws `JITValidationError`. Async variants settle promise schemas. `issues`
offers iterable consumption over the same compiled issue vector.

## Structural operations

| API                    | Result                  | Allocation strategy            |
| ---------------------- | ----------------------- | ------------------------------ |
| `JIT.compare.equal(S)` | boolean                 | early return, no result object |
| `JIT.clone(S)`         | deep shape clone        | allocates required output only |
| `JIT.compare.diff(S)`  | change entries          | allocates only differences     |
| `JIT.update(S)`        | immutable updated value | shares untouched branches      |
| `JIT.compare.hash(S)`  | numeric structural hash | scalar accumulator             |

Hints such as `entity`, `keyed`, `ordered`, `indexBy` and `hash` influence
strategies for repeated collection operations. Benchmark index construction
against expected reuse; a single lookup may be cheaper as a scan. The
[cache, hash and indexes guide](/docs/runtime/cache-hash-index) documents the
immutability contract, adaptive threshold and invalidation choices.

## Explicit artifact groups

Operations are independent callable artifacts. Group only the capabilities a
module exports; `{ ... }` is also the grouped AOT marker.

```ts
const ReadUser = {
  is: JIT.validate.is(User),
  parse: JIT.validate.parse(User),
  equal: JIT.compare.equal(User),
};

ReadUser.parse(input);
ReadUser.equal(left, right);
// ReadUser.clone does not exist
```

Composable artifacts such as `JIT.map.many(...)` or a JSON pipeline can be
grouped alongside validation and query functions. AOT lowers each complete
ExecutionPlan and emits only the declared properties.

## Collection changes

```ts
const watchUsers = JIT.watch(JIT.array(User), { key: "id" });
const changes = watchUsers(previousUsers, currentUsers);

const members = JIT.watchedList(JIT.array(User), previousUsers, {
  key: "id",
});
members.add(newUser);
```

`watch` compiles a stateless O(n) snapshot diff and can be emitted as a pure
AOT function when it has no callbacks. `watchedList` retains state for an
aggregate or unit of work. See [watched lists and collection
changes](/docs/runtime/watched-lists) for identity rules and configuration.

For state owned by one process or UI store, `JIT.update(User).reactive(initial)`
adds typed path watchers, selectors, batching and configurable scheduling over
the compiled immutable updater. See [reactive updates](/docs/runtime/reactive-updates).

## JSON and codecs

```ts
JIT.json.stringify(User);
JIT.json.parse(User).validate();
JIT.json.stringifyChunks(Users);
JIT.codec(Event, { version: 2 });
```

JSON stringify bakes known keys and punctuation into source. Chunked JSON keeps
large array output bounded. The binary codec is a persisted wire contract with
a version byte; binary rowsets are process-local and may evolve independently.

## Mapper and transform

```ts
const toPublic = JIT.map(UserEntity, PublicUser, {
  name: { from: "fullName" },
});
const toPublicMany = JIT.map.many(UserEntity, PublicUser, {
  name: { from: "fullName" },
});

toPublic(entity);
toPublicMany(entities);
```

Mapper output is whitelisted by the destination schema. `JIT.map.many()` emits
one bulk indexed loop while `JIT.map()` omits the array loop entirely.
`JIT.transform` provides field operations and selection
over one source schema.

`JIT.dto(Target)` annotates an ordinary boundary schema. Apply `JIT.validate.parse`,
`JIT.json`, or `JIT.binary` directly; use `JIT.map` and `JIT.map.many` for
whitelist projections from an entity schema. See [DTO schemas](/docs/runtime/dtos)
for schema variants, security boundaries, and AOT behavior.

## Security operations

```ts
const SafeLog = JIT.security.mask(User);
const CleanForm = JIT.security.sanitize(Form);
```

`.pii("redact" | "mask" | "hash")` controls field masking. Sanitization
rebuilds only marked paths. These operations reduce accidental data exposure,
but application authorization and context-specific HTML policy remain separate
responsibilities.

## Aggregated exports

```ts
export const User = {
  is: JIT.validate.is(UserSchema),
  parse: JIT.validate.parse(UserSchema),
  equal: JIT.compare.equal(UserSchema),
};
```

The object exposes only declared operations. AOT emits only those properties
and required helpers. Standalone exports keep their exact declaration name.
