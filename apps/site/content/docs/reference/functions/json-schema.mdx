---
title: JSON Schema
description: Two-way bridge between a JIT schema and a JSON Schema document.
---

`JIT.jsonSchema` bridges both directions, so a contract has one source of
truth whichever side it starts on.

## `to` — schema to document

```ts
const User = JIT.object({
  id: JIT.number().int32().positive(),
  email: JIT.string().email(),
  role: JIT.union(JIT.literal("admin"), JIT.literal("member")),
});

JIT.jsonSchema.to(User);
```

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "properties": {
    "id": { "type": "integer", "format": "int32", "exclusiveMinimum": 0 },
    "email": { "type": "string", "format": "email" },
    "role": { "anyOf": [{ "const": "admin" }, { "const": "member" }] }
  },
  "required": ["id", "email", "role"],
  "additionalProperties": false
}
```

| Option                 | Default           | Purpose                                                       |
| ---------------------- | ----------------- | ------------------------------------------------------------- |
| `target`               | `"draft-2020-12"` | also `draft-07`, `draft-04`, `openapi-3.0`                    |
| `io`                   | `"output"`        | describe the produced value, or the accepted one (`"input"`)  |
| `unsupported`          | `"throw"`         | `"any"`, or a function returning a node / `"any"` / `"throw"` |
| `cycles`               | `"ref"`           | `"throw"` to refuse a schema that cannot be inlined           |
| `reused`               | `"inline"`        | `"ref"` extracts repeated schemas into the defs               |
| `override`             | —                 | last word over every node                                     |
| `ref`                  | —                 | turns a schema `id` into an external `$ref` URI               |
| `dialect`              | auto              | emit the `$schema` keyword                                    |
| `additionalProperties` | auto              | force the object policy                                       |

### What is representable

A type is representable exactly when JIT's own JSON serializer defines a wire
form for it. `JIT.date()` becomes `{ "type": "string", "format": "date-time" }`
because that is what `JIT.json.stringify` writes. `bigint`, `symbol`, `Map`,
`Set`, `File`, `Promise` and friends have no wire form, so they go through the
`unsupported` policy — which throws by default, with the path in the message.

A document that claimed `{}` for a `Set` would tell consumers "anything goes"
about a field the validator rejects, so silence is not an option.

### Targets

Each protocol version is one capability descriptor; the emitter never branches
on a version name. Adding a version is adding a descriptor.

| Capability       | 2020-12       | draft-07      | draft-04      | OpenAPI 3.0   |
| ---------------- | ------------- | ------------- | ------------- | ------------- |
| definitions      | `$defs`       | `definitions` | `definitions` | `definitions` |
| `$ref` siblings  | yes           | `allOf` wrap  | `allOf` wrap  | `allOf` wrap  |
| single value     | `const`       | `const`       | `enum: [v]`   | `enum: [v]`   |
| tuples           | `prefixItems` | `items: []`   | `items: []`   | `items: []`   |
| exclusive bounds | number        | number        | boolean       | boolean       |
| null             | type union    | type union    | type union    | `nullable`    |
| examples         | `examples`    | `examples`    | `examples`    | `example`     |

## `from` — document to schema

```ts
const User = JIT.jsonSchema.from({
  type: "object",
  properties: { name: { type: "string" }, age: { type: "number" } },
  required: ["name", "age"],
} as const);

const isUser = JIT.validate.is(User);
// (value: unknown) => value is { name: string; age: number }
```

The document already states the shape, so the type is read from the literal
rather than declared twice. Pass it `as const` and every compiled operation is
typed from it.

Constraints become the same specialized checks a hand-written schema produces:
`format: "email"` compiles to the email check, not to a runtime interpreter.

### `refine`

```ts
JIT.jsonSchema.from(contract, {
  refine: ({ node, path, schema }) =>
    node.type === "integer" && path.at(-1) === "amount"
      ? JIT.custom<number>((value) => (value as number) % 2 === 0, "must be even").schema
      : schema,
});
```

`refine` runs for every node after the structural conversion; returning a
schema replaces the built one. `unknownKeywords: "throw"` refuses a document
with keywords the converter does not implement.

### AOT

`from` resolves entirely at generation time: the generated module contains the
specialized functions and no document.

## Known limits

- External `$ref` URIs are refused rather than fetched.
