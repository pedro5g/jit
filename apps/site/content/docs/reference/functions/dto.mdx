---
title: dto
description: Mark a schema as an application boundary without adding a compiler facade.
---

## Input DTO

```ts
const CreateUserDTO = JIT.dto(CreateUser);
const parseCreateUser = JIT.json.parse(CreateUserDTO).validate();

const command = parseCreateUser(request.body);
```

DTO is ordinary schema metadata. Use it with every capability namespace:
`JIT.validate.is`, `JIT.validate.parse`, `JIT.json`, `JIT.binary`, and `JIT.compare.hash`.

## Output DTO

```ts
const PublicUserDTO = JIT.dto(PublicUser);
const encodePublicUser = JIT.from(UserEntity)
  .map(PublicUserDTO, { displayName: { from: "name" } })
  .to.json();

const json = encodePublicUser(entity);
```

Mapping is a target whitelist, preventing undeclared entity fields from
leaking. `JIT.map.many` provides the specialized bulk form.

## DTO metadata

The annotation identifies an application boundary without creating a second
DTO compiler, execution IR, optimizer, or operation aggregator. The same
ExecutionPlan is used whether the target schema is DTO-annotated or not.

## Performance

`many` emits a fused indexed mapping loop. JSON and binary sinks are
specialized from the DTO target, which avoids serializing private source fields
and then deleting them.

## AOT

Export a composed artifact from a `*.jit.ts` file. AOT consumes its descriptor
and emits only the transport/mapping stages it uses.

See [DTO schemas](/docs/runtime/dtos) for inbound/outbound design patterns.
