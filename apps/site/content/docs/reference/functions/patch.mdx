---
title: patch
description: Three patch contracts that disagree about null, under three explicit names.
---

## Signature

```ts
const User = JIT.object({ id: JIT.number(), name: JIT.string() });

const applyPatch = JIT.patch.apply(User);
const mergePatch = JIT.patch.merge(User);
const jsonPatch = JIT.patch.json(User);
```

| Member  | Contract                    | What `null` means             |
| ------- | --------------------------- | ----------------------------- |
| `apply` | deep partial                | an ordinary value             |
| `merge` | RFC 7396 JSON Merge Patch   | **remove the member**         |
| `json`  | RFC 6902 JSON Patch         | an ordinary value in an op    |

They are separate names because they disagree, and code that treats them as
interchangeable deletes fields it meant to keep.

## apply — a deep partial

`JIT.patch.apply` is [`JIT.update`](./update) under this namespace: the same
compiled plan, not a second engine. A member left out is left alone.

```ts
const User = JIT.object({ id: JIT.number(), name: JIT.string() });
const applyPatch = JIT.patch.apply(User);

console.log(JSON.stringify(applyPatch({ id: 1, name: "Ada" }, { name: "Ada L" })));
```

## merge — RFC 7396

An object member is merged recursively; `null` removes; anything else replaces.

```ts
const Address = JIT.object({ city: JIT.string(), zip: JIT.string() });
const User = JIT.object({ id: JIT.number(), name: JIT.string(), address: Address });
const mergePatch = JIT.patch.merge(User);

const user = { id: 1, name: "Ada", address: { city: "London", zip: "E1" } };

console.log(JSON.stringify(mergePatch(user, { address: { city: "Paris" } })));
console.log(JSON.stringify(mergePatch(user, { name: null })));
console.log(mergePatch(user, {}) === user);
```

The last line is worth noting: nothing changed, so the original value comes back
by reference and a caller can skip downstream work with `===`.

## json — RFC 6902

Operations are applied in order against JSON Pointers.

```ts
const User = JIT.object({ id: JIT.number(), name: JIT.string(), tags: JIT.array(JIT.string()) });
const jsonPatch = JIT.patch.json(User);

const user = { id: 1, name: "Ada", tags: ["a"] };

console.log(JSON.stringify(jsonPatch(user, [{ op: "replace", path: "/name", value: "Grace" }])));
console.log(JSON.stringify(jsonPatch(user, [{ op: "add", path: "/tags/-", value: "b" }])));
console.log(JSON.stringify(jsonPatch(user, [{ op: "remove", path: "/tags/0" }])));
```

`test` compares structurally and throws naming the pointer that failed:

```ts
const User = JIT.object({ id: JIT.number(), name: JIT.string() });
const jsonPatch = JIT.patch.json(User);

try {
  jsonPatch({ id: 1, name: "Ada" }, [{ op: "test", path: "/name", value: "Nope" }]);
} catch (error) {
  console.log((error as Error).message);
}
```

Unlike the rest of this library there is little to specialize here — a pointer
is a string that arrives with the patch, so it is parsed and walked at run time.
`json` is here for the RFC contract and because the AOT output carries the whole
implementation with no dependency on JIT, not because compiling makes it faster.

## All three are immutable

```ts
const User = JIT.object({ id: JIT.number(), tags: JIT.array(JIT.string()) });
const jsonPatch = JIT.patch.json(User);

const user = { id: 1, tags: ["a"] };
jsonPatch(user, [{ op: "add", path: "/tags/-", value: "b" }]);

console.log(user.tags.length);
```
