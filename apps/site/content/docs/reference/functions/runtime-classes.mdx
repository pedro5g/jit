description: Materialize a schema as a validated runtime class without reflection.

## Runtime classes

`JIT.class(schema)` generates a constructor-first class whose constructor
assigns fields in schema order. It has no default factory aliases.

```ts
const UserSchema = JIT.object({
  id: JIT.string().default("generated"),
  name: JIT.string().min(2),
});

const User = JIT.class(UserSchema).use(JIT.class.equals, JIT.class.with);

const ada = new User({ name: "Ada" });
const grace = ada.with({ name: "Grace" });

ada.equals(grace); // false
```

Capabilities are explicit, installed once on the prototype, and reuse the
structural compilers: `equals`, `hashCode`, `diff`, `with`, and
`identity("field")`. `with` accepts the schema-derived update patch type; readonly
schema fields cannot be patched and are preserved by the compiled update.

## Accessors

`accessors()` rematerializes a class with its configured backing layout. Private
fields use JavaScript `#` slots; getters and setters are emitted directly on the
prototype, including in AOT output. Per-field settings override `default`.

```ts
const Account = JIT.class(
  JIT.object({ id: JIT.string(), passwordHash: JIT.string() }),
).accessors({
  default: { field: "private", get: "public", set: "protected" },
  fields: {
    id: { set: false },
    passwordHash: { get: "protected", set: "protected" },
  },
});

const account = new Account({ id: "a_1", passwordHash: "..." });
account.id; // "a_1"
```

## Construction factories

Calling `.factories(...)` changes the class to factory-only construction.
Creation resolves defaults; hydration requires complete persisted state and
does not apply creation defaults. The configured names are the only aliases:

```ts
const User = JIT.class(UserSchema).factories({
  create: "make",
  hydrate: "restore",
});

User.make({ name: "Ada" });
User.restore({ id: "u_1", name: "Ada" });
// new User(...) is rejected by TypeScript and at runtime.
```

Runtime and AOT preserve the same configured names.

## DDD factories

The domain-oriented factories live under `JIT.ddd`: `JIT.ddd.valueObject`,
`JIT.ddd.entity`, `JIT.ddd.aggregateRoot`, and `JIT.ddd.domainEvent`. They are
presets over the same runtime-class machinery, grouped because they are a
vocabulary — someone reaching for an entity is not shopping among the schema
factories.

`JIT.class` stays at the top level. It is the primitive the presets configure,
and DTOs, JSON pipelines and AOT class artifacts build on it without any
domain meaning attached.

```ts
const UserBase = JIT.ddd.entity(
  JIT.object({ id: JIT.string(), name: JIT.string() }),
  { id: "id" },
);

class User extends UserBase {}

const user = User.create({ id: "u_1", name: "Ada" });
user.identity; // "u_1"
```

## Abstract classes

Use `JIT.class.abstract(schema)` for a domain base. Its static factories use
polymorphic `this`, so subclasses receive their own instance type.

```ts
const UserBase = JIT.class.abstract(UserSchema).factories({
  create: "create",
  hydrate: "hydrate",
});

class User extends UserBase {
  greeting() {
    return `Hello ${this.name}`;
  }
}

User.create({ name: "Ada" }).greeting();
```

The abstract base itself cannot create or hydrate an instance.

## Value objects

`JIT.ddd.valueObject(schema)` is a concrete, frozen runtime class with structural
equality and hash code enabled by default.

```ts
const Money = JIT.ddd.valueObject(
  JIT.object({
    amount: JIT.number(),
    currency: JIT.enum(["BRL", "USD"]),
  }),
);

const price = Money.create({ amount: 10, currency: "BRL" });
Object.isFrozen(price); // true
```

## Entities

`JIT.ddd.entity(schema, { id })` creates an abstract base with identity semantics.
Identity is intentionally distinct from structural equality.

```ts
const UserBase = JIT.ddd.entity(
  JIT.object({ id: JIT.string(), name: JIT.string() }),
  { id: "id" },
);

class User extends UserBase {}

User.create({ id: "u_1", name: "Ada" }).sameIdentity(
  User.create({ id: "u_1", name: "Grace" }),
); // true
```

## Domain events

`JIT.ddd.domainEvent(type, { payload, version })` creates a frozen class whose
schema contains `id`, literal `type`, literal `version`, `occurredAt`, and the
validated payload. Creation accepts only the payload; id and time are resolved
by defaults.

```ts
const OrderConfirmed = JIT.ddd.domainEvent("order.confirmed", {
  payload: JIT.object({ orderId: JIT.string().min(1) }),
  version: 1,
});

const event = OrderConfirmed.create({ orderId: "o_1" });

event.type; // "order.confirmed"
event.version; // 1
event.payload.orderId; // "o_1"
event["~event"].type; // "order.confirmed"
```

## Aggregate roots

`JIT.ddd.aggregateRoot(schema, { id })` creates an abstract entity base with
identity, an ordered pending-event queue, and a compiled in-place `update()`.
Subclass methods express the domain transition, then raise the event that
describes it. Readonly schema fields remain unavailable to `update()`.

```ts
const OrderBase = JIT.ddd.aggregateRoot(
  JIT.object({
    id: JIT.string().readonly(),
    status: JIT.enum(["draft", "confirmed"]),
  }),
  { id: "id" },
);

class Order extends OrderBase {
  confirm() {
    this.update({ status: "confirmed" });
    this.raise({ type: "order.confirmed" });
  }
}

const order = Order.create({ id: "o_1", status: "draft" });
order.confirm();
order.pullEvents(); // [{ type: "order.confirmed" }]
```

`peekEvents()` returns a snapshot without clearing it. `pullEvents()` returns
the queued events in insertion order and resets the queue.

## AOT

Runtime classes are AOT artifacts too. Pass a class to `AOT.generate()` and
the generated module contains a plain specialized class: validation,
construction, selected capabilities, and aggregate event storage are emitted
locally, with no JIT runtime import. Generated Domain Events preserve
`create(payload)` and `hydrate(state)`; direct construction and `hydrate()` use
the complete persisted event envelope. Value Objects, Entities, Aggregate
Roots, and Domain Events are factory-only by default.
