## validate

```ts
const isUser = JIT.validate.is(User);
const parseUser = JIT.validate.parse(User);
const safeParseUser = JIT.validate.safeParse(User);
```

`JIT.validate` is a capability namespace. Each method returns a callable,
lazy artifact; `.compile()` is optional eager warm-up and `.plan` exposes the
same descriptor consumed by AOT.

| Selection                | Return                | Failure behavior              | Output transforms      |
| ------------------------ | --------------------- | ----------------------------- | ---------------------- |
| `is(schema)`             | type predicate        | `false`, first failure        | checks current input   |
| `parse(schema)`          | inferred output       | throws `JITValidationError`   | yes                    |
| `safeParse(schema)`      | success union         | returns issue vector          | yes                    |
| `parseAsync(schema)`     | output promise        | rejects with validation error | yes                    |
| `safeParseAsync(schema)` | success-union promise | resolves with issues          | yes                    |
| `issues(schema)`         | iterator              | yields only issues            | no extra public vector |

Use `is` in hot filtering and guards. Use `safeParse` at user-controlled
boundaries where callers need paths and messages. Use `parse` where invalid
data is exceptional and a central error handler already owns the response.

```ts
const result = safeParseUser(input);

if (!result.success) {
  for (const issue of result.issues) {
    console.error(issue.path, issue.code, issue.message);
  }
} else {
  result.data; // JIT.Typeof<typeof User>
}
```

The compiler orders cheap checks before expensive checks and emits direct
property access for known object fields. `is` returns early and never allocates
an issue array. For pure non-transforming schemas, `parse` reuses that fast
success path and only builds issues after failure. Observable callbacks,
stateful regexes and transforming schemas remain single-pass. `safeParse`
rebuilds output only when defaults, coercions or transforms require it.

## Canonical paths

Validation operations are available only through `JIT.validate`. The removed
root-level spellings are documented only in the [migration guide](../../guides/migrating-to-2);
current code should use:

```ts
const isUser = JIT.validate.is(User);
const parseUser = JIT.validate.parse(User);
const safeParseUser = JIT.validate.safeParse(User);
```

## Async schemas

Promise wrappers require an async selection:

```ts
const Job = JIT.object({
  result: JIT.promise(JIT.object({ id: JIT.string() })),
});

const parseJob = JIT.validate.parseAsync(Job);
const job = await parseJob(input);
```

`JIT.validate.async.parse(Job)` remains a compatibility spelling. Sync parsing
does not silently await promises.

## Cache and AOT

Validator selections use the schema-identity compile cache. Reuse the schema
and compiled function; do not construct them per request. In AOT files,
self-contained `refine`, transform, coerce and default callbacks are emitted as
local bindings. Generated functions import no JIT runtime.

```ts
// user.jit.ts
import { JIT } from "@jit-compiler/jit/define";

export const isUser = JIT.validate.is(User);
```

After `jit generate`, import `isUser` from the configured output directory.
