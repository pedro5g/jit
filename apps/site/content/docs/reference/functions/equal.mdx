title: equal
description: Compile allocation-free structural equality for one schema.
---

## Signature

```ts
const equalUser = JIT.equal(User);
// (left: User, right: User) => boolean
```

`JIT.equal(schema)` emits equality code from the known shape. Objects use
direct field access, arrays use indexed loops, tuples unroll fixed positions
and tagged unions dispatch before comparing variant fields.

```ts
equalUser(
  { id: 1, profile: { name: "Ada" } },
  { id: 1, profile: { name: "Ada" } },
); // true
```

## Semantics

- primitives follow their schema domain;
- `Date` compares timestamps;
- arrays and tuples are ordered; a tuple's known arity unrolls to static
  indices, so it costs no loop;
- a `record` compares key sets before values, so two records with the same
  values under different keys are not equal;
- a `Set` compares size then membership, which is identity-based, exactly as
  JavaScript defines set membership;
- a `Map` compares size and key identity, but its values go through the value
  schema, so a map of objects compares structurally;
- optional, nullable and default states remain distinct where the schema says
  they are distinct;
- entity/key hints can enable keyed comparison for collections;
- custom equality hints override only the annotated branch.

Equality expects values already in the schema output domain. Validate an
unknown value before comparing it.

## Performance

The generated function allocates no result object and exits on the first
difference. Known keys avoid `Object.keys`, recursive generic dispatch and
string path construction. Repeated calls therefore contain only the work
required by the shape.

```ts
const explain = equalUser.explain();
explain.operation; // "equal"
explain.cache; // "identity"
equalUser.hash; // deterministic source hash
```

Compile once at module scope. Calling `JIT.equal(User)` again with the same
schema identity reuses the compiled cache.

## Collections and indexes

```ts
const Users = JIT.array(User).keyed("id");
const equalUsers = JIT.equal(Users);
```

`keyed` is useful when order does not express identity and snapshots are
compared repeatedly. Index construction has a cost; a plain ordered array is
usually faster for one small comparison. Never mutate a cached collection
behind the compiler's back.

## Comparing a subset

`select()` compares only the named fields. The others are not compared and
discarded — they are absent from the generated comparison entirely, so a wide
row with one meaningful status field costs one comparison rather than twenty:

```ts
const User = JIT.object({
  id: JIT.number(),
  status: JIT.string(),
  notes: JIT.string(),
});

const sameStatus = JIT.compare.equal(User).select("id", "status");

console.log(sameStatus({ id: 1, status: "active", notes: "a" }, { id: 1, status: "active", notes: "b" }));
console.log(sameStatus({ id: 1, status: "active", notes: "a" }, { id: 1, status: "blocked", notes: "a" }));
```

A dotted path reaches into a nested object:

```ts
const Profile = JIT.object({ name: JIT.string(), bio: JIT.string() });
const User = JIT.object({ id: JIT.number(), profile: Profile });

const sameName = JIT.compare.equal(User).select("profile.name");

console.log(sameName({ id: 1, profile: { name: "Ada", bio: "x" } }, { id: 2, profile: { name: "Ada", bio: "y" } }));
```

The selection is the same one [`JIT.project`](./project) and
[`JIT.cqrs.query().select()`](./query) resolve, so the fields you compare by
are the fields you project.

## Which fields changed

`JIT.compare.changed` answers *what* moved rather than just whether anything
did, as a bitmask. Testing a field is one bitwise operation, and the comparison
allocates nothing:

```ts
const User = JIT.object({
  id: JIT.number(),
  email: JIT.string(),
  tags: JIT.array(JIT.string()),
});

const userChanged = JIT.compare.changed(User);

const before = { id: 1, email: "ada@x.com", tags: ["a"] };
const after = { id: 1, email: "grace@x.com", tags: ["a"] };
const mask = userChanged(before, after);

console.log(userChanged.has(mask, "email"), userChanged.has(mask, "tags"));
console.log(userChanged.fields.join(","));
```

A structural field is compared by value, so a rebuilt array with the same
contents is not a change. `select()` watches a subset, including dotted paths.

## AOT

```ts
// models.jit.ts
export const equalUser = JIT.equal(User);
```

AOT writes the same specialized body as a pure export. No schema object,
compiler or cache implementation remains in the consumer bundle.
