```ts
const User = JIT.object({
  id: JIT.number().int32().positive(),
  name: JIT.string().min(3).max(80),
  email: JIT.string().email(),
  role: JIT.union(JIT.literal("admin"), JIT.literal("member")),
});

type User = JIT.Typeof<typeof User>;
```

The runtime AST has a stable `{ type, _type, def, annotations }` shape. `_type` is
always `null` at runtime and carries inference only at compile time.

## Input, output and updates

One schema has three useful TypeScript views. `Input` is the boundary value
accepted by creation and parsing, `Typeof` is the resolved state, and
`Update` is the immutable patch shape. Defaults make a field optional only
for input; readonly fields are removed from updates, even when `readonly()` is
wrapped by `default()` or another transparent wrapper.

```ts
import { JIT, type Input, type Typeof, type Update } from "@jit-compiler/jit";

const User = JIT.object({
  id: JIT.string().readonly().default("generated"),
  name: JIT.string(),
  nickname: JIT.string().optional(),
  note: JIT.string().nullish(),
});

type CreateUser = Input<typeof User>;
// { id?: string; name: string; nickname?: string; note?: string | null }

type UserState = Typeof<typeof User>;
// { readonly id: string; name: string; nickname: string | undefined; note: string | null | undefined }

type ChangeUser = Update<typeof User>;
// { name?: string; nickname?: string; note?: string | null }
```

`new (JIT.class(schema))(input)` accepts `Input`. When a class opts into
`.factories(...)`, its create factory accepts `Input` and its hydrate factory
accepts complete persisted state. Hydration validates invariants but never
fills a missing default, which prevents a truncated stored record from silently
becoming a newly-created entity.

## Object transforms

```ts
User.partial();
User.partial("email");
User.required();
User.pick("id", "name");
User.omit("email");
User.extend({ active: JIT.boolean() });
```

Transforms return new schemas and do not mutate the original.

## Composition

Use `union`, `xor`, `intersection`, `not`, `when/where`, refinements, codecs and
template literals as declarative schema nodes. TypeScript rejects invalid literal
defaults when their value can be checked statically against string/number constraints.

```ts
JIT.string().min(5).default("hello");
// JIT.string().min(5).default("no"); // TypeScript error
```

Runtime validation remains authoritative for dynamic strings and numbers whose literal
value is not known to TypeScript.
