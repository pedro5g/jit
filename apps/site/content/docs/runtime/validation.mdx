```ts
const isUser = JIT.validate.is(User);
const parseUser = JIT.validate.parse(User);
const safeParseUser = JIT.validate.safeParse(User);

isUser(input);
parseUser(input);
safeParseUser(input);
```

Each artifact lowers only the requested validator operation; it does not compile
serializers, hash functions, or unrelated variants.

```ts
const isUser = JIT.validate.is(User);
const safeParseUser = JIT.validate.safeParse(User);
const issues = JIT.validate.issues(User);
```

Validation is reached through `JIT.validate` and nowhere else — there are no
root-level `is`/`parse`/`safeParse` aliases. Each factory returns one callable
artifact.

The unprefixed members are synchronous, and the awaited pair lives under
`async`, so a call site never has to read a suffix to know which one it runs:

```ts
const parseUser = JIT.validate.parse(User);
const parseUserAsync = JIT.validate.async.parse(User);
```

Every artifact it returns also implements
[Standard Schema](https://standardschema.dev) through `~standard`, so it can be
handed directly to any consumer in the ecosystem:

```ts
const isUser = JIT.validate.is(User);

isUser["~standard"].validate({ id: 1 }); // { value } | { issues }
```

The adapter is the schema's own, shared by identity, and it closes over the
compiled `safeParse` — there is no second, generic validator behind it.

`is` is fail-fast and allocation-free on the normal path. `safeParse` collects stable
issues with `path`, `code`, `expected` and `message`. `parse` throws
`JITValidationError`. Promise schemas use the asynchronous variants.

The `~standard` adapter closes over the compiled `safeParse` function; it does not run a
second generic validator.

## Select the smallest operation

| Need                           | Compile        | Failure behavior             |  Happy-path allocation |
| ------------------------------ | -------------- | ---------------------------- | ---------------------: |
| Boolean gate                   | `is`           | `false` on first mismatch    |                   none |
| Typed value or exception       | `parse`        | throws with issues           |    transform-dependent |
| Typed result without exception | `safeParse`    | issue vector                 |    transform-dependent |
| Promise schemas                | async variants | Promise result/error         |        async machinery |
| Consume issue records          | `issues`       | iterator                     | validator issue vector |

Do not compile `safeParse` for a hot boolean branch merely because it is the
most familiar API. `is` can return as soon as one cheap check fails.

## Issue handling

```ts
const result = safeParseUser(input);

if (!result.success) {
  for (const issue of result.issues) {
    fields.set(issue.path.join("."), issue.message);
  }
}
```

Use stable `code` values for program behavior and custom `message` text for
users. `path` is a root-relative readonly `PropertyKey[]`; array positions stay
numeric and no consumer has to parse a formatted path string.

For large untrusted inputs, `JIT.validate.safeParse(Schema, { maxIssues: 100 })`
and the equivalent `parse`, async and factory options stop traversal at the
limit. Without the option diagnostics continue to collect all independent
issues.

## Transforming parsers

Defaults, coercion, trim/case conversion, masks and pipes make output differ
from input. The generated validator tracks whether rebuilding is necessary and
returns the original reference when no transform changed the value.

For a JSON boundary, compose decoding and validation without another public
wrapper:

```ts
const parseUserJson = JIT.json.parse(User).validate();
```

This lowers to one generated execution function: native `JSON.parse` followed
immediately by the specialized validator. Runtime compilation performs a
bounded best-effort warm-up for the declared object shape. See
[composable execution](/docs/runtime/composable-execution) for support and
physical fusion boundaries.

## Standard Schema

Frameworks can call `schema["~standard"].validate(value)`. JIT's adapter uses
the already compiled validator, so interoperability does not introduce a
generic validation layer.

## Measured cost

On Node 22.17.1 / Ryzen 7 5800H, `pnpm bench:validate` measured standalone AOT
`safeParse` at 50.41 ns / 312 B for one issue and 95.14 ns / 856 B for five.
The equivalent handwritten five-field validator measured 62.96 ns and 80.96
ns. Custom messages stayed within noise of default messages. `maxIssues: 2`
reduced the five-error AOT sample to 448 B but took 185 ns on the tiny object;
it is a memory/DoS bound for large invalid inputs, not a small-input speedup.

## Security notes

Validation proves the declared shape, not authorization or business ownership.
Avoid echoing raw received values in public issue messages. Opaque custom
predicates should be deterministic and free of side effects because validators
may be cached and reused across requests.
